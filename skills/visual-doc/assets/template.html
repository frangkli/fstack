Render reports in a background job

Report requests wait for the whole PDF. A job returns the request at once.

Status
Proposed
As of
2026-10-13; nothing deployed
Scope
API and worker; no schema change

What we build. The API queues the render and returns 202 with a status URL.

Why. Render takes 250 of 340 ms of a request today. [source: command, commit, sample size]

Where things live after the change

Browser

Posts /reports, then polls the status URL until the PDF is ready.

↓ POST /reports

api

  • Validates the request
  • Queues a job, returns 202

Service api · unchanged except the route

render-worker new

Claims a job, renders the PDF, stores it, marks the job done. Retries a failed render at most twice.

Service render-worker · one replica

A concrete request: POST /reports for report 42
  1. api validates {"template": "monthly", "account": 7} and inserts job 42 as queued.
  2. It returns 202 {"status": "/reports/42"}.
  3. render-worker claims job 42, stores reports/42.pdf and marks it done.
  4. The next poll of /reports/42 returns {"state": "done", "url": "…"}.
